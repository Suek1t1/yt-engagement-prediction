# サムネイル Vision メタデータ 全件取得の依頼仕様

`likes_thumb_meta.py`（サムネイル内容特徴の本採用）を全5,817件で正式評価するために、
班員の Vision API パイプラインで下記データを拡張取得してほしい、という依頼仕様。

## 背景
- 現在の `thumbnail_features_1000.csv` は 811ユニーク動画ぶんのみ（ランダム1000件由来）。
- 811件では時系列70/30単発評価しかできず、log R² がマイナスで効果を断定できない。
- 全5,817件（重複除去後のユニーク動画数）が揃えば rolling-origin 全fold評価へ自動で切り替わり、
  「サムネイル内容がタイトル/タグを超える増分を持つか」をリークなしで判定できる。

## 取得対象
- 対象 video_id: `english_titles.csv` を video_id で重複除去した **5,817件すべて**
  （現状の811件を含む。差分の約5,000件が新規取得ぶん）。
- ソース画像: `thumbnail_link`（`https://i.ytimg.com/vi/<video_id>/default.jpg`）。

## 出力フォーマット（現行CSVと同一・列を変えない）
```
video_id,likes,thumbnail_link,extracted_text,labels,web_entities
```
- `extracted_text`: サムネイル上のOCR文字（空でも可）
- `labels`: Vision の画像ラベル（Pythonリスト文字列 `['Yoga','Exercise',...]`）
- `web_entities`: Web Detection の固有名詞（同上）
- ファイル名: `thumbnail_features_full.csv`（別名で置けば `likes_thumb_meta.py` の
  `THUMB_CSV` を差し替えるだけ。列が同じならコード改修不要）。

## 鉄則（リーク防止・このデータ特有）
- **likes を Vision のプロンプト/処理に一切渡さない**（投稿前情報だけで特徴を作る）。
- 動画重複は video_id で除去済みの5,817件に対して取得（同一動画の複数行を作らない）。
- 取得後の評価は `likes_thumb_meta.py` が自動で
  重複除去→trending順時系列分割→rolling-origin で行うので、班員側で分割・学習は不要。

## 受領後の作業（こちら側）
1. `thumbnail_features_full.csv` をリポジトリ直下に配置。
2. `likes_thumb_meta.py` の `THUMB_CSV` を差し替えて実行 → 全fold平均が出る。
3. 合格ライン: アカウント+サムネメタ（構成3）が アカウント+タイトル/タグ（構成4）と
   チャンネル平均だけの下限（正規プロトコル ρ 0.553）を安定して上回るか。
4. 結果を講義日報・README（Phase16）に反映。

## 補足
- ViT の768次元ベクトル（pkl）を別途もらえれば、そちらも正規プロトコルで再評価可能
  （班員報告の R²=0.64 は重複リークの疑いが濃いため、要リークなし再評価）。
  ただし本採用したのは軽量・解釈可能な Vision メタデータのほう。
